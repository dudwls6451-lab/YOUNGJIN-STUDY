# v11.60.63 — 학습목표 수정 / 항공사 과정 복구

기존 v11.60.61과 IR Gleim v11.60.62 추가 패치가 적용된 저장소에 사용하는 변경 파일 패치입니다.

## 적용

ZIP 안의 index.html, assets/, data/를 GitHub 저장소 최상위에 같은 경로로 올려 덮어쓰세요. 폴더 전체를 삭제하거나 교체하지 마세요. GitHub Pages 배포가 끝나면 웹은 새로고침하고 앱은 완전히 종료 후 다시 실행하세요. APK 재설치·SQL 실행은 필요 없습니다.

IR 문제·그림·추가 스크립트는 직전 v11.60.62 패치 파일을 계속 사용합니다. 이번 index.html에는 해당 스크립트 연결도 포함했습니다.

## 변경

- 마이페이지 > 공부 기간과 목표에 ‘목표 수정’ 버튼을 추가했습니다. 저장된 기간·교재·진도율·정답률·알림을 불러와 수정한 뒤 ‘수정한 목표 저장’을 누르면 됩니다.
- ‘수정 취소’는 저장된 설정으로 돌아갑니다. 수정 중 입력은 이력 갱신 때문에 초기화되지 않습니다. 기간 변경은 기존 풀이 이력을 새 기간으로 재집계하며 풀이 기록을 삭제하지 않습니다.
- 저장 시 기존 계정 설정 동기화 경로를 사용하며 홈의 기간별 진도·일일 목표와 앱 알림 예약을 다시 계산합니다. 연결 실패 시 기존 동기화 모듈의 재시도 안내를 확인하세요.
- 트리니티 문제 307개와 제주항공 복기 200개를 별도 데이터 파일에서 ID 중복 없이 병합합니다. 기존 주 데이터 파일에는 이 두 과정이 없어 버튼을 눌러도 빈 과정이 열렸던 문제를 수정했습니다.
- 별도 파일을 못 읽으면 기존 questions.json으로 재시도합니다. 과정 버튼에서도 재시도하며, 모두 실패하면 선택 화면을 유지하고 안내합니다.
- 기존 ID의 문항은 덮어쓰지 않습니다. 신고 오류 수정과 관리자 수정본은 기존 적용 순서를 유지합니다.

## 검증

Chromium PC 1440px / 모바일 390px에서 실제 기본·항공사·CPL·IR 데이터와 수정된 앱 본체를 사용해 검증했습니다. 트리니티 진입·출제·채점, 목표 생성·수정·취소·재접속 유지, 잘못된 날짜 거부, 홈 반영, 오류 후 재시도, 원본 데이터 대체 로딩, IR 960문항 유지, 밝은/어두운 테마와 가로 넘침 검사를 통과했습니다.

로그인·서버 서비스는 테스트용 대역을 사용했습니다. 실제 계정 간 동기화와 Android 기기 동작을 이번 검사에서 직접 실행하지는 않았습니다. 기존 동기화·APK 코드는 변경하지 않았습니다. 상세 결과: validation-v11-60-63.json.
